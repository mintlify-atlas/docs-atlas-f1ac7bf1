---
title: "Multipart upload: large file handling"
description: "S3 multipart upload API for large files. Initiate an upload, send parts in parallel, then complete or abort. Each part receives an IPFS CID as its ETag."
---

Multipart upload is the recommended path for files larger than 5 GB. You split the file into parts, upload each one independently (in parallel if you like), then assemble them with a single completion call. On the gateway side, assembly is instant: it creates an IPLD DAG node linking to the individual part CIDs — no data is copied or concatenated. Each uploaded part receives its own IPFS CID as an `ETag`, giving you content-addressable deduplication at the part level. All endpoints require a Bearer JWT with the appropriate OAuth 2.0 scope.

## Upload flow

<Steps>
  <Step title="Initiate the upload">
    Call `POST /{bucket}/{key}?uploads` to receive an `UploadId`. This ID ties all parts together and must be included in every subsequent request.
  </Step>
  <Step title="Upload parts">
    Call `PUT /{bucket}/{key}?uploadId={id}&partNumber={n}` for each part. Parts must be at least 5 MB except the final part. Parts can be uploaded in any order and in parallel. Save the `ETag` (IPFS CID) returned for each part — you will need them in step 3.
  </Step>
  <Step title="Complete or abort">
    Call `POST /{bucket}/{key}?uploadId={id}` with an ordered XML list of `PartNumber`/`ETag` pairs to finalize the upload. The gateway builds an IPLD DAG and returns the composite object's location and ETag.

    Alternatively, call `DELETE /{bucket}/{key}?uploadId={id}` at any point to abort the upload and unpin all uploaded parts.
  </Step>
</Steps>

## POST /{bucket}/{key}?uploads — CreateMultipartUpload

Initiates a new multipart upload session and returns an `UploadId`.

**Auth:** `storage:write` scope — `Authorization: Bearer <token>`

### Parameters

<ParamField path="bucket" type="string" required>
  Destination bucket name.
</ParamField>

<ParamField path="key" type="string" required>
  Destination object key.
</ParamField>

<ParamField header="Content-Type" type="string">
  MIME type of the final assembled object.
</ParamField>

<ParamField header="x-amz-meta-*" type="string">
  User-defined metadata to attach to the final object (prefix with `x-amz-meta-`).
</ParamField>

### Response codes

| Status | Meaning |
|--------|---------|
| `200` | Upload initiated. Response body contains `InitiateMultipartUploadResult` XML with `UploadId` |

### Example

```bash curl
curl --request POST \
  --url 'https://gateway.fx.land/my-bucket/large-file.bin?uploads' \
  --header 'Authorization: Bearer <token>' \
  --header 'Content-Type: application/octet-stream'
```

**Response body:**

```xml 200 OK
<?xml version="1.0" encoding="UTF-8"?>
<InitiateMultipartUploadResult xmlns="http://s3.amazonaws.com/doc/2006-03-01/">
  <Bucket>my-bucket</Bucket>
  <Key>large-file.bin</Key>
  <UploadId>VXBsb2FkIElEIGZvciBpbGx1c3RyYXRpb24</UploadId>
</InitiateMultipartUploadResult>
```

## PUT /{bucket}/{key}?uploadId={id}&partNumber={n} — UploadPart

Uploads a single part. Parts can be uploaded in any order and concurrently. Every part (except the last) must be at least 5 MB. The `ETag` in the response is the IPFS CID of that part — store it for the CompleteMultipartUpload call.

**Auth:** `storage:write` scope — `Authorization: Bearer <token>`

### Parameters

<ParamField path="bucket" type="string" required>
  Destination bucket.
</ParamField>

<ParamField path="key" type="string" required>
  Destination object key.
</ParamField>

<ParamField query="uploadId" type="string" required>
  Upload ID from CreateMultipartUpload.
</ParamField>

<ParamField query="partNumber" type="number" required>
  Part number between 1 and 10,000. Parts are assembled in ascending part-number order during CompleteMultipartUpload.
</ParamField>

<ParamField header="Content-Length" type="number" required>
  Byte length of the part body. Minimum 5,242,880 (5 MB) except for the last part.
</ParamField>

<ParamField header="Content-MD5" type="string">
  Base64-encoded MD5 digest for integrity verification.
</ParamField>

### Response codes

| Status | Meaning |
|--------|---------|
| `200` | Part uploaded. `ETag` response header contains the part's IPFS CID |
| `400` | Part too small, invalid `uploadId`, or invalid `partNumber` |

### Example

```bash curl
curl --request PUT \
  --url 'https://gateway.fx.land/my-bucket/large-file.bin?uploadId=VXBsb2FkIElEIGZvciBpbGx1c3RyYXRpb24&partNumber=1' \
  --header 'Authorization: Bearer <token>' \
  --header 'Content-Length: 5242880' \
  --data-binary @part1.bin
```

## POST /{bucket}/{key}?uploadId={id} — CompleteMultipartUpload

Finalizes a multipart upload by providing an ordered list of part numbers and their ETags. The gateway validates that all parts are present and correctly ordered, then creates an IPLD DAG node linking to the part CIDs. Assembly is instant — no data is concatenated on disk.

The composite `ETag` uses the format `{BLAKE3-hash-of-CIDs}-{partCount}`.

**Auth:** `storage:write` scope — `Authorization: Bearer <token>`

### Parameters

<ParamField path="bucket" type="string" required>
  Destination bucket.
</ParamField>

<ParamField path="key" type="string" required>
  Destination object key.
</ParamField>

<ParamField query="uploadId" type="string" required>
  Upload ID from CreateMultipartUpload.
</ParamField>

### Request body

An XML document with one `<Part>` element per uploaded part, listed in ascending `PartNumber` order.

```xml request body
<?xml version="1.0" encoding="UTF-8"?>
<CompleteMultipartUpload>
  <Part>
    <PartNumber>1</PartNumber>
    <ETag>"bafybeigdyrzt5sfp7udm7hu76uh7y26nf3efuylqabf3oc"</ETag>
  </Part>
  <Part>
    <PartNumber>2</PartNumber>
    <ETag>"bafkreihxvh4d5pqhkhxqfdy3yzpfmam5a6t3wbmtj7d3iur"</ETag>
  </Part>
</CompleteMultipartUpload>
```

### Response codes

| Status | Meaning |
|--------|---------|
| `200` | Upload assembled. Response body contains `CompleteMultipartUploadResult` XML |
| `400` | Invalid part list, missing parts, or out-of-order part numbers |

### Example

```bash curl
curl --request POST \
  --url 'https://gateway.fx.land/my-bucket/large-file.bin?uploadId=VXBsb2FkIElEIGZvciBpbGx1c3RyYXRpb24' \
  --header 'Authorization: Bearer <token>' \
  --header 'Content-Type: application/xml' \
  --data '<?xml version="1.0" encoding="UTF-8"?>
<CompleteMultipartUpload>
  <Part>
    <PartNumber>1</PartNumber>
    <ETag>"bafybeigdyrzt5sfp7udm7hu76uh7y26nf3efuylqabf3oc"</ETag>
  </Part>
  <Part>
    <PartNumber>2</PartNumber>
    <ETag>"bafkreihxvh4d5pqhkhxqfdy3yzpfmam5a6t3wbmtj7d3iur"</ETag>
  </Part>
</CompleteMultipartUpload>'
```

**Response body:**

```xml 200 OK
<?xml version="1.0" encoding="UTF-8"?>
<CompleteMultipartUploadResult xmlns="http://s3.amazonaws.com/doc/2006-03-01/">
  <Location>https://gateway.fx.land/my-bucket/large-file.bin</Location>
  <Bucket>my-bucket</Bucket>
  <Key>large-file.bin</Key>
  <ETag>"a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6-2"</ETag>
</CompleteMultipartUploadResult>
```

## DELETE /{bucket}/{key}?uploadId={id} — AbortMultipartUpload

Cancels an in-progress multipart upload and unpins all parts that were already uploaded. Call this if you encounter an error mid-upload or decide not to complete it, to avoid retaining orphaned IPFS blocks.

**Auth:** `storage:write` scope — `Authorization: Bearer <token>`

### Parameters

<ParamField path="bucket" type="string" required>
  Bucket containing the in-progress upload.
</ParamField>

<ParamField path="key" type="string" required>
  Object key of the in-progress upload.
</ParamField>

<ParamField query="uploadId" type="string" required>
  Upload ID to abort.
</ParamField>

### Response codes

| Status | Meaning |
|--------|---------|
| `204` | Upload aborted and parts unpinned |

### Example

```bash curl
curl --request DELETE \
  --url 'https://gateway.fx.land/my-bucket/large-file.bin?uploadId=VXBsb2FkIElEIGZvciBpbGx1c3RyYXRpb24' \
  --header 'Authorization: Bearer <token>'
```

## GET /{bucket}?uploads — ListMultipartUploads

Lists all in-progress multipart uploads for a bucket. Useful for identifying and cleaning up stalled uploads.

**Auth:** `storage:read` scope — `Authorization: Bearer <token>`

### Parameters

<ParamField path="bucket" type="string" required>
  Bucket to inspect.
</ParamField>

<ParamField query="max-uploads" type="number" default="1000">
  Maximum number of uploads to return.
</ParamField>

<ParamField query="key-marker" type="string">
  Return only uploads for keys after this value.
</ParamField>

<ParamField query="upload-id-marker" type="string">
  Combined with `key-marker` for pagination of uploads sharing the same key.
</ParamField>

### Response codes

| Status | Meaning |
|--------|---------|
| `200` | List returned as `ListMultipartUploadsResult` XML |

### Example

```bash curl
curl --request GET \
  --url 'https://gateway.fx.land/my-bucket?uploads' \
  --header 'Authorization: Bearer <token>'
```

## GET /{bucket}/{key}?uploadId={id} — ListParts

Lists the parts already uploaded for a specific multipart upload. Use this to check upload progress or to resume an interrupted session.

**Auth:** `storage:read` scope — `Authorization: Bearer <token>`

### Parameters

<ParamField path="bucket" type="string" required>
  Bucket containing the upload.
</ParamField>

<ParamField path="key" type="string" required>
  Object key of the in-progress upload.
</ParamField>

<ParamField query="uploadId" type="string" required>
  Upload ID to inspect.
</ParamField>

<ParamField query="max-parts" type="number" default="1000">
  Maximum number of parts to return per page.
</ParamField>

<ParamField query="part-number-marker" type="number">
  Return parts with part numbers greater than this value (for pagination).
</ParamField>

### Response codes

| Status | Meaning |
|--------|---------|
| `200` | Part list returned as `ListPartsResult` XML |

### Example

```bash curl
curl --request GET \
  --url 'https://gateway.fx.land/my-bucket/large-file.bin?uploadId=VXBsb2FkIElEIGZvciBpbGx1c3RyYXRpb24' \
  --header 'Authorization: Bearer <token>'
```
